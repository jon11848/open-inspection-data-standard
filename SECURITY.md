# Security Policy

Do not publish exploitable vulnerabilities, private credentials, signed evidence URLs, customer inspection records, or regulated personal information in a public issue.

For the initial personal-GitHub working draft, report security concerns privately to the repository owner. Before the public launch, replace this paragraph with a monitored project security address and define an acknowledgment and disclosure process.

The data model is not itself an authorization protocol. Implementations must independently address authentication, authorization, tenant isolation, encryption, audit logging, evidence-access expiration, malware scanning, rate limiting, and applicable privacy or records laws.
